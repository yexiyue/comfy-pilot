# 08 · 人工反馈、中断与恢复
对应 M2。目标：让创作任务真正支持异步协作。

## 知识与术语
**Human-in-the-loop（人工介入）**让用户在关键决策点反馈。
**Interrupt（中断）**保存必要进度并等待外部输入。
**Resume（恢复）**使用用户的决定继续任务。
**Checkpoint（检查点）**是运行状态的持久记录。
**Thread（执行线程标识）**在这里用于关联连续运行状态，不是操作系统线程。
**Stale decision（过期决定）**是针对旧状态或旧版本的反馈。
**Concurrency（并发）**例如两个网页同时修改同一创作任务。

## 在 ComfyPilot 中
生成完候选后等待用户；用户隔天选图时明确携带候选版本身份。任务已被另一页面推进时，旧反馈不能静默覆盖新状态。

中断是图运行机制，不能自动暂停已经提交到 ComfyUI 的外部任务。恢复时某些节点逻辑可能重新执行，所以提交任务不应因恢复重复发生。

## 设计问题
刷新后待反馈卡片从哪里重建？用户修改简报后，旧候选的“接受”动作是否仍有效？拒绝与取消有何区别？

## 常见误区
进程内 Promise 等待等于持久中断；用内存保存器却宣称支持服务重启；所有等待状态都等于生成停止。

## 学完的验收
描述正常回复、隔天回复、重复点击和过期反馈四种情况。能解释哪些信息必须在浏览器之外保存。
