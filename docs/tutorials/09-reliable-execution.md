# 09 · 异步执行、重试与任务对账
对应 M3。目标：处理执行结果未知的真实系统。

## 知识与术语
**Async job（异步任务）**提交与完成在不同时间发生。
**Correlation ID（关联标识）**连接应用 run、job 与 ComfyUI prompt_id。
**Timeout（超时）**表示等待结束，不证明外部任务未执行。
**Retry（重试）**再次尝试操作。
**Idempotency（幂等性）**重复请求不会产生额外预期外效果。
**Reconciliation（对账）**比较本地记录与外部任务实际状态。
**Backoff（退避）**逐渐拉长重试间隔。
**Cancellation（取消）**请求停止任务；是否真正停止需要确认。

## 在 ComfyPilot 中
提交后断线，ComfyUI 可能仍然出图。系统应先根据已知 ID 查询历史或队列。提交响应丢失且没有可关联 ID 时，状态应标记为未知，不能声称完全保证不重复。

应用侧幂等键有用，但不能假设 ComfyUI 天然识别它。外部提交和本地记录之间存在失败窗口，必须在设计中承认并处理。

## 错误分类
可暂时恢复：连接抖动。需改变条件：显存不足。需补齐能力：模型或节点缺失。需用户决定：任务预算耗尽。不同错误不使用同一无限重试策略。

## 设计问题
只有当前 job 的取消权限吗？共享 ComfyUI 的全局中断会不会影响其他任务？断开的前端重新连接后怎样获取最新状态？

## 学完的验收
给出提交超时、生成中断线、完成后下载失败、重复点击四类故障的处理表。重试次数有限，未知状态对用户可见。
