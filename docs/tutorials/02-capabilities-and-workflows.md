# 02 · ComfyUI 能力与工具边界
对应 M0。目标：把本地工作流变成可理解、可校验的工具。

## 知识与术语
**Capability（能力）**描述系统实际能完成什么，例如文生图、参考图变体、局部重绘。
**Workflow template（工作流模板）**是验证过的节点组合。
**Schema（结构定义）**描述参数类型、范围和必填项；TypeScript 静态类型不能代替外部输入的运行时校验。
**Precondition（前置条件）**包括已安装节点、模型文件与必需输入。
**Seed（随机种子）**影响采样随机过程；模型、节点、软件环境等变化仍可能改变结果。
**Adapter（适配层）**把应用语义转换成 ComfyUI 请求与结果。
**Capability discovery（能力发现）**是读取实际环境，不能靠模型猜测已安装能力。

## 在 ComfyPilot 中
工具应表达“使用已验证模板生成横版封面”，而不是把所有节点和整个文件系统交给模型。每个工具说明适用场景、参数限制、输出和失败原因。

API 执行用的工作流表示与编辑器保存的图形信息可能不同。了解两者用途即可，具体导出和接入在开发时讨论。

## 设计问题
什么证据证明能保持构图？图生图是否真的满足精准编辑要求？工具结果应该返回图片引用、任务 ID 还是完整日志？

## 常见误区
节点存在不等于依赖完整；同名工作流不代表相同版本；重新文生图不能冒充局部编辑。

## 学完的验收
为一个可运行工作流写能力卡：输入、输出、可调参数、资源要求、限制和验证样例。此时不要求自动生成工作流。
