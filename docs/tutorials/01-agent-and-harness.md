# 01 · 从聊天到 agent：系统全貌
对应 M0。目标：理解系统各层，而不是记住框架名称。

## 知识与术语
**LLM（大语言模型）**根据输入生成响应或工具调用请求。模型提出调用不等于程序已经执行。
**Tool（工具）**是系统暴露的、有明确输入输出的能力。
**Workflow（工作流）**由程序规定主要步骤。
**Agent**根据观察结果在允许范围内决定下一步。
**Harness**是让 agent 可控运行的循环、上下文策略、工具环境、状态、限制和验证机制。业界定义有差异，本项目采用这个工程范围。
**Orchestration（编排）**负责协调步骤、状态与外部任务。
**Policy（策略）**规定允许什么、何时停止；框架机制不能替你决定策略。

## 在 ComfyPilot 中
从需求生成提示词再调用一次工作流，主要是固定流程。收到“保持风格但换构图”后，结合能力和当前版本选择下一步，是 agent 决策。保证它不丢进度、不无限出图、不能调用未验证工作流，是 harness 职责。

## 设计问题
哪些决策交给模型？哪些规则必须由程序执行？用户在哪些节点掌握最终决定？

## 常见误区
有聊天框不等于有 agent；用了 LangGraph 不等于有完整 harness；多 agent 数量不是系统成熟度指标。

## 学完的验收
用一张图标出用户、模型、应用服务和 ComfyUI，解释“提议执行”和“实际执行”的区别。

## 本项目的技术映射
LangChain 提供模型、消息与工具基础组件；LangGraph 组织任务执行；Skills 提供领域方法；ComfyUI 执行图像工作流。应用自身仍需承担上下文策略、参数校验、任务对账和资产管理。

学习时先在 [04A](04a-langchain-components.md) 理解基础组件，再到 [05](05-agent-loop.md) 学习编排，避免把“用了框架”误认为已经理解循环。
