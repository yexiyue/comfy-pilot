# 02B · 产品载体与 NestJS 工程化骨架
对应 M0B，在能力盘点后、单次创作闭环前学习。目标：明确代码、进程和数据边界。本文是设计与验收计划，不代表工程已实现。

## 载体与选型
首版采用本地 Web 工作台：React + Vite、NestJS 常驻后端、SQLite 业务存储及本地图片目录。浏览器适合候选图比较、多轮反馈和运行检查，也能复用前端经验。当前无需服务端页面渲染，不引入额外全栈页面框架。

选 NestJS 是为了学习模块划分、依赖注入与应用生命周期。首版使用默认 Express HTTP 适配器，有明确插件或性能需求时再评估 Fastify。NestJS 组织应用，LangGraph 组织创作流程，ComfyUI 执行图像计算。需要安装包、托盘或系统集成时再评估 Tauri；云端部署另需解决用户本机计算资源连接与账号管理。

## 知识与术语
- **模块化单体**：按职责划分模块，先在同一个应用进程运行。
- **Module**：声明内部组件和对外提供的服务。
- **Controller**：接收请求，处理协议输入与响应。
- **Provider / 依赖注入**：容器提供服务及其依赖，方便组合实现和替换测试对象。
- **DTO / 运行时校验**：定义接口结构并检查外部输入；TypeScript 类型不能代替运行时校验。
- **后台执行器**：独立于某次请求领取和处理任务的组件，不等同于独立进程。

框架机制参见 [Modules](https://docs.nestjs.com/modules) 与 [Providers](https://docs.nestjs.com/providers)。

## 规划中的工程结构
```text
app/
  web/                      React + Vite
  server/                   NestJS
    src/
      projects/             项目、简报、反馈
      runs/                 运行记录、调度、对账与恢复
      agent/                LangGraph、上下文、Skills 与工具
      comfy/                ComfyUI HTTP / WebSocket 适配
      assets/               图片、版本与文件存储
      storage/              数据库连接与持久化实现
packages/
  contracts/                应用自有请求、响应与事件定义
```

共享协议不暴露 NestJS Provider、数据库实体或 LangGraph 内部对象。RunsModule 调用 AgentModule，后者使用 ComfyModule 等服务；避免反向依赖整个 RunsModule 形成循环。纯参数校验与状态转换尽量保留为独立函数。

## 请求与任务生命周期
1. 请求通过校验后持久化待执行记录，再返回任务 ID。
2. 后台执行器领取记录，运行编排并保存外部任务映射；限制并发，避免同一记录被重复领取。
3. 浏览器订阅状态事件；断开只结束订阅，不能销毁任务。
4. 重开页面读取权威状态；事件带稳定 ID 或序号，处理重复、乱序与缺失，必要时重新获取快照。
5. 服务重启先核对未完成任务；有外部 ID 时查队列与历史，提交结果不明则标记未知，不盲目重提。

API 与执行器首版同进程。持久任务记录是恢复依据，不能只启动无人跟踪的 Promise。关闭整个服务会停止本地编排，但 ComfyUI 可能继续运行；关机不能保证任务完成。

NestJS 的 [SSE](https://docs.nestjs.com/techniques/server-sent-events) 不提供事件持久化或任务恢复。AI SDK UI 对话流需做协议适配，见 [11](11-product-experience.md)；完整故障语义在 [09](09-reliable-execution.md) 验收。

## 数据与配置
- SQLite 保存业务记录，图片、缩略图和工作流快照放数据目录，通过资产 ID 引用。
- LangGraph 用持久化 checkpointer 保存图进度；不能以进程内 MemorySaver 声称支持重启恢复，具体后端与安装版本兼容性在实现时核实。
- 数据目录独立于构建输出；备份覆盖业务记录、检查点和资产。先停写再备份或使用数据库备份机制，恢复时核对引用。
- 数据库结构用版本化迁移管理，更新应用不能清空任务与图片。
- 启动时校验 ComfyUI 地址、模型配置、数据目录及预算；密钥只在服务端，不进入前端构建或日志。
- 默认监听回环地址，校验允许的 Host / Origin，对修改操作提供适当请求保护；资产接口按 ID 定位受控目录，不直接读取任意传入路径。

业务数据与检查点的分工见 [架构文档](../architecture.md) 和 [LangGraph 持久化](https://docs.langchain.com/oss/javascript/langgraph/persistence)。

## 开发与交付
开发时分别运行 Vite 与 NestJS，通过开发代理访问 API；发布时由 NestJS 同源提供构建后的页面、API 和事件流。启动入口检查配置与连通性后打开浏览器；首版不负责安装或启动用户已有的 ComfyUI。

锁定依赖及支持的 Node.js 版本，提供不含密钥的配置示例。检查包括类型检查、构建、关键状态转换与模拟 ComfyUI 的集成案例；真实 GPU 出图单独验证。日志关联 project、run、job 和外部 prompt_id，避免记录密钥与不必要的图片内容。

退出时停止领取新任务，保存可恢复状态并关闭连接；异常退出依靠持久化与启动对账，不能依赖退出钩子必然执行。

## 设计问题
页面、NestJS 和 ComfyUI 分别关闭会发生什么？哪些记录是权威状态？如何避免并发领取？重复点击与提交响应丢失有何区别？怎样用替身验证故障而不消耗 GPU？

## 学完的验收
1. 解释浏览器、NestJS、ComfyUI 与存储的边界及模块依赖。
2. 页面可访问 API，无效输入返回清晰错误，配置密钥不进入前端。
3. 模拟任务先记录再执行，页面断开后仍能完成，重开可查结果。
4. 服务重启后记录仍在，未完成任务可识别；完整外部对账留到 M3。
5. 说明开发与发布启动的差别，用替身检查重复请求与外部失败。

首版不引入微服务、Redis 队列和独立 worker；出现明确隔离、吞吐或部署需求后再评估。
