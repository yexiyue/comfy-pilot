# 04A · LangChain 基础组件与职责边界

对应 M1；在任务状态之后、[05 · Agent 循环](05-agent-loop.md) 之前阅读。目标：理解基础积木，知道它们怎样进入 LangGraph 的运行过程。只介绍概念与验收，不包含实现代码。

## 本项目的明确选择
使用 LangChain 的 Models、Messages、Tools，配合 LangGraph 自建创作循环。暂不使用 LangChain 的高层 createAgent。两者配合是本项目的设计选择，不是所有 agent 的必选组合。

LangChain 既有基础组件，也有预先组合好的 agent；LangGraph 提供更显式的执行组织方式。学习基础组件不意味着要把框架所有功能学完。

## Models：模型接口
**Chat model（聊天模型）**接收带角色的消息，返回文本、结构化内容或工具调用请求。
**Provider（供应商适配）**处理不同模型服务的请求和响应差异。
**Streaming（流式输出）**逐步返回内容；部分输出不能直接当成最终完整参数执行。
**Structured output（结构化输出）**约束结果形状，内容仍需业务验证。

统一接口降低调用差异，但不会让所有模型拥有相同的图像理解、工具调用或结构化输出能力。ComfyPilot 需要实际核实所选模型。

## Messages：消息
**System message**承载行为规则，**Human/User message**表达用户输入，**AI/Assistant message**承载模型响应，**Tool message**承载工具执行结果。实际类型以所用接口为准。

**Tool call ID**关联某次工具请求与返回结果。历史裁剪不能随意留下没有对应关系的工具请求或结果，具体要求应遵循模型服务协议。

完整历史、数据库状态和本轮发送的消息集合是不同对象。Messages 提供表示方式，信息选择由应用决定。

## Tools：工具
**Tool name / description**帮助模型判断工具用途。
**Input schema**描述输入参数类型与约束。
**Execution function（执行函数）**完成真正的动作。
**Tool result**返回结果或可处理的错误信息。

在本项目中，生成工具连接 ComfyUI 适配层；它可以先返回外部任务标识，由应用跟踪生成结果。声明工具不会自动执行请求，也不能替代参数检查、权限、预算和异常处理。

## 为什么先不使用 createAgent
createAgent 是高层 agent 入口，提供标准循环及相关扩展方式，适合快速搭建通用助手。本项目先显式组织循环，目的是看清：
- 模型调用时看到哪些消息和工具。
- 工具结果如何改变状态。
- 哪些错误应修正，哪些应停止。
- 什么时候等待用户，什么时候等待外部生成。

以后标准循环能满足需求时，可以重新评估高层封装；这不是对 createAgent 能力的否定。

## “LangChain 管理记忆”该怎样理解
消息抽象、裁剪或摘要能力、长期存储、检索策略处于不同层次。LangGraph 检查点关注会话状态与运行进度，Store 或业务存储承载长期信息。哪些事实值得记住、如何处理旧偏好，需要应用设计。

部分 LangChain 中间件服务于 createAgent 生命周期；自建图需要明确接入相应处理，不能假定安装依赖就会自动管理记忆。

## 练习与验收
用“把第二张图改成暖色”描述一次往返：
1. 应用识别稳定资产 ID，读取现有约束。
2. 组织本轮消息与允许的工具，通过模型接口调用。
3. 模型提出工具请求，程序校验和执行。
4. 保留结果关联，更新任务状态。
5. 图根据结果进入继续判断、等待生成或等待用户阶段。

能给每一步标注组件、编排机制或业务策略；能解释模型支持、参数正确与外部任务成功是三个不同判断。

## 常见误区
统一模型接口代表所有模型能力相同；工具调用请求等于已经生成图片；引入 LangChain 就有完整记忆；LangGraph 必须搭配 createAgent；前端消息可以不加处理直接成为全部模型上下文。
