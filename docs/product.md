# ComfyPilot 产品文档
规划版本：0.3；日期：2026-09-13。状态：待实践验证，仅完成文档规划。

## 产品定位
面向个人创作者的图片创作工作台。用户描述目标、比较候选图、提供反馈，助手协调本地 ComfyUI 完成多轮创作，并保留要求、版本和过程。

首个场景是博客封面创作。目标是完成可持续迭代的创作任务，而不仅是把自然语言转换为一次出图请求。

## 用户与问题
首位用户是具备前端经验的开发者本人，已有本地 ComfyUI，想在真实应用中学习 agent 与 harness。

需要解决的问题：
- 创作要求散落在聊天里，修改时容易遗忘已经确认的约束。
- 多次出图后，不清楚哪张图来自哪次修改、使用了什么工作流。
- 页面关闭、服务重启或生成失败后，创作进度难以继续。
- 模型为什么选择一个工具、为什么生成结果不符合要求，缺少可检查的依据。

## 核心用户旅程
1. 创建创作项目，说明封面主题、用途、尺寸和偏好。
2. 助手整理创作简报，突出缺失信息与关键约束。
3. 基于已验证的本地能力选择工作流，提交少量候选图。
4. 用户查看结果，选择某张图继续修改或接受交付。
5. 助手将反馈解释为明确的约束变化，并保存新版本关系。
6. 用户稍后返回，继续同一个任务，或下载已接受的图片。

示例：用户要求“Rust 与 AI 主题、简洁、横图、右侧留白”，选中第二张后提出“保留构图、颜色更暖”。系统记录第二张为本轮基准图，并明确该工作流是否具备保留构图的能力。若只能文生图，应说明新图是重新生成的变体，不能承诺精准编辑。

## MVP 功能
| 功能 | 最小行为 |
|---|---|
| 创作简报 | 记录主题、用途、尺寸、风格、约束与待确认项 |
| 能力目录 | 只暴露本地已验证的工作流与可修改参数 |
| 出图任务 | 提交、展示进度、识别完成和失败、获取产物 |
| 候选画廊 | 选图、查看版本来源、下载图片 |
| 多轮反馈 | 明确当前版本与本轮改动，保留已确认要求 |
| 任务持久化 | 页面重开后找回任务、图片和待处理反馈 |
| 开发检查视图 | 查看本轮模型输入、工具调用、状态变化与错误 |

首版默认单用户、本地使用、单 agent。生成批量和尝试次数设上限；数值在本地性能验证后确定。

## 暂缓功能
首版载体为本机运行、浏览器打开的 Web 应用。应用服务运行时，关闭页面不应停止后台任务；服务重启恢复依赖持久化与外部任务对账。桌面安装包与云端部署后续再评估。

任意生成 ComfyUI 工作流、自动安装模型与节点、复杂多 agent、视频、模型训练、公开多用户平台和付费计费。局部重绘、参考图控制、放大、自动视觉检查都作为能力验证后的扩展。

## 产品规则
- 用户的明确约束优先于自动审图意见；冲突时呈现冲突，等待选择。
- “提交成功”“执行完成”“取得图片”“用户接受”是不同状态。
- 不把生成成功等同于质量合格，也不承诺相同 seed 必然逐像素复现。
- 自动重试与自动修改都消耗资源，必须有次数或时间预算。
- 图片与持久状态是主要产物，聊天记录用于交流和追踪。
- 本地图像生成不等于所有数据本地处理。若使用云端语言或视觉模型，应明确哪些提示词、参考图和结果图会被发送。

## 成功标准
用户能完成“提出需求 → 获取候选 → 选择 → 修改 → 接受”的闭环；重开页面后可以继续；每张图片可追溯到任务、输入和版本；异常情况下不会静默丢失任务或无界重复生成。

画质用用户选择率和任务约束符合度评价；工程质量用任务恢复、重复提交、状态一致性等案例评价。没有评测基线前，不设置虚构的成功率指标。

## 待验证假设
本地服务地址与可达性；可用模型与工作流；单次运行时间和资源占用；是否已有编辑能力；语言模型及视觉模型的本地或云端方案。这些在路线图 M0 确认。

## 创作技能扩展（M2）
在单次创作闭环完成后，增加一项项目内维护的“博客封面设计”技能，承载构图、留白、提示词组织和检查方法。用户继续使用自然语言提出需求，无需先理解或手动挑选技能。

技能按当前任务加载，默认审美建议不能覆盖用户明确要求。开发检查视图展示技能选择及版本，普通界面只解释与创作有关的决定。

此阶段以验证“按需提供专业知识”是否改善多轮创作为目标，不增加技能市场、自动安装或自动改写技能等范围。

## 技术分工与学习目标
- LangChain：接入模型、组织消息、定义可调用工具。
- LangGraph：显式组织创作循环、任务状态、人工反馈与恢复。
- Skills：提供按需加载的专业方法。
- ComfyUI：执行已验证图像工作流。
- React + Vite / AI SDK UI：展示对话、任务、图片及反馈；事件协议由服务端适配。
- NestJS：组织 API、业务模块、依赖注入与后台执行器；首版采用默认 Express HTTP 适配器。
- SQLite + 本地资产目录：保存业务记录与图片；图检查点使用持久化后端，与业务存储明确分工。

工程化学习见 [02B](tutorials/02b-engineering-foundation.md)，首版采用模块化单体。

首阶段用 LangChain 基础组件配合 LangGraph 自建循环，暂不采用 createAgent 高层循环。这是为了掌握每轮上下文与状态的流转，后续可依据实际复杂度重新评估。
