# 学习与产品路线图

路线以阶段验收为准，不设固定工期。已有 UI 和模型调用经验可以复用；先完成一个可靠闭环，再扩展能力。

| 阶段 | 学习篇章 | 产物 | 通过条件 |
|---|---|---|---|
| M0 能力盘点 | 01、02 | 本地能力清单与一个验证过的工作流 | 知道可用模型、参数、输出及限制，能区分文生图与编辑 |
| M0B 工程化骨架 | 02B | React + Vite / NestJS 工程边界、配置、存储与启动方案 | 页面可访问 API；任务记录跨重启保留；模拟任务不随页面断开而取消 |
| M1 单次创作闭环 | 03、04、04A、05 | 简报、LangChain 模型与工具组件、LangGraph 创作循环、候选画廊 | 能解释消息与工具调用，完成出图并追溯输入；程序校验与模型决策分工清楚 |
| M2 多轮创作与上下文 | 06、06A、07、08 | 版本树、反馈、待审阅状态与一项创作技能 | 连续多轮保留约束，准确识别基准图，重开页面可继续；技能按需加载且不覆盖用户要求 |
| M3 可靠运行 | 09 | 外部任务映射、恢复和预算规则 | 断线后找回任务，状态未知时不会立即重复生成 |
| M4 评测与产品体验 | 10、11 | 固定评测集、运行检查视图、清晰交互 | 可定位上下文或工具错误，区分执行成功与创作成功 |
| M5 Harness 总结与扩展 | 12 | 架构复盘、协议与迁移决策 | 能解释系统策略，替换一个模块后核心案例仍通过 |

## 每阶段的工作节奏
阅读概念 → 写出设计决定 → 当场讨论实现 → 做最小功能 → 用反例检查 → 保存结论。不要因章节全部读完就跳过验收。

## 贯穿项目的案例
1. 基础要求：简洁横版博客封面，右侧留白。
2. 增量修改：变暖色，但保留之前的明确约束。
3. 版本引用：从第二张候选分支，而不是默认使用最新生成图。
4. 能力不足：要求精准局部编辑，但本地只有文生图。
5. 上下文增长：多轮反馈中重复或过时信息逐渐增多。
6. 用户改意：明确撤销旧约束后，不再被旧记忆覆盖。
7. 执行中断：页面断开，但外部生成仍在进行。
8. 结果不确定：提交请求超时，不知道任务是否已进入队列。
9. 资源耗尽：达到生成预算时停止并说明原因。
10. 审图冲突：自动检查合格，但用户不满意；用户判断仍然有效。

11. 技能误触发：无关任务不加载技能全文，相关任务按需读取。
12. 技能与约束冲突：默认配色建议不覆盖用户明确的黑白要求；技能提到的工具缺失时说明限制。

## 能力进阶
M0B 用模拟任务验证工程边界；M1 接入真实生成，M3 完成外部任务对账、未知状态与重试验收。

M1 主要是工作流应用；M2 加入依据上下文进行选择的 agent 行为；M3–M4 构成可靠 harness 的主要工程训练；M5 才考虑更开放的能力。

图像编辑与自动审图是独立能力分支，依赖本地模型和外部模型方案。没有它们也能完成主线。自动生成任意工作流、视频、多 agent 不作为毕业要求。

## 毕业标准
能够画出一次创作运行的流程，并解释每一步的输入、输出、持久状态和模型上下文；能从失败轨迹区分需求理解、上下文组装、工具执行和图像质量问题；能给出有证据的修复方案。
